# Админ-панель

Команде нужно видеть, что происходит с приложением, и разбираться с обращениями в поддержку:
сколько людей пришло и занимается, что с аккаунтом конкретного человека («пропала орбита»,
«не дали капсулу»). Сейчас для этого есть только Firebase Console: сырые документы, без сводок,
и любая правка руками ломает связи, которые держит сервер (опыт ↔ уровень, орбита ↔ щиты).

## Первая версия — только просмотр

1. **Обзор:** аккаунты (всего, новые и активные за 1/7/30 дней, регистрации по дням за 30 дней,
   способ входа), профили в базе, тренировки (всего и за 7 дней), десять последних регистраций.
2. **Пользователь:** поиск по email, @username или uid → аккаунт, прогресс, награды,
   учёба в цифрах, последние тренировки.

Действий (выдать щит, вернуть капсулу, переименовать, отключить аккаунт) пока нет — см. «Дальше».

## Кто админ

- Права — **custom claim** `admin: true` в Firebase Auth. Он лежит в подписанном токене входа:
  клиент не может его ни подделать, ни выдать себе.
- Выдаёт и снимает права скрипт `scripts/admin/grant-admin.mjs` (Admin SDK); кнопки в приложении нет.
  При снятии прав скрипт отзывает сессии (`revokeRefreshTokens`): старый токен с claim перестаёт
  работать сразу, а не через час.
- Сервер проверяет токен с `checkRevoked` — на одну проверку больше, чем у обычных функций,
  но только для админских запросов.
- После выдачи прав токен в браузере ещё старый. Страница `/admin` при открытии обновляет токен
  (`getIdTokenResult(true)`), поэтому достаточно открыть её по адресу; пункт в «Ещё» появится после этого.

## Значки команды

- Две роли, обе — claims: `admin` (админ-панель) и `staff` (значок «Команда Dakuta»).
  **Админ всегда в команде** (`rolesOf` в `server/core/admin.ts`): выдать админку — значит и значок,
  убрать из команды — значит и админку. Скрипт: `--staff` — только значок, `--revoke` — снять админку
  (значок остаётся), `--revoke --staff` — убрать из команды совсем.
- В шапке профиля, в одной строке с титулом: «Команда Dakuta» (инверсная плашка с логотипом Dakuta)
  и «Админ». Это отметки, а не награды: их не получить за практику и не надеть как титул.
- Роли читаются из собственного токена, поэтому значки видит только сам человек. Когда появятся
  публичные профили (`feature/social`), роли нужно будет зеркалить в серверное поле профиля
  (`serverOwnedFields` в правилах), которое пишет скрипт.
- Новый значок появляется, когда обновится токен: в течение часа или после повторного входа
  (у админа — сразу при открытии `/admin`).
- Тексты значков — часть продукта: на en, ru, uk и no (`profile.team`).

## Сервер

- `server/http.ts` → `adminHandler()`: POST, токен, claim `admin`, иначе 401 / 403.
- `server/core/admin.ts` — чистые функции (тесты): разбор поискового запроса, сводка по аккаунтам,
  вид профиля, учёбы и тренировки для панели.
- `server/admin-panel.ts` — чтение через Admin SDK, журнал.
- `POST /api/admin-overview` → сводка. Аккаунты — из Firebase Auth (`listUsers`, страницами по 1000,
  не больше 20 страниц): это не тратит чтения Firestore. Профили и тренировки — `count()`
  (одно чтение на 1000 записей).
- `POST /api/admin-user` `{ query }` → `{ found: false }` или `{ found: true, user }`.

Тренировки за 7 дней — запрос по группе коллекций `sessions` с фильтром `createdAt`. Для него нужен
индекс уровня группы коллекций (`firestore.indexes.json`), его выкладывают отдельно:
`firebase deploy --only firestore:indexes`. Пока индекса нет, панель показывает «нужен индекс»,
остальное работает.

### Журнал

Каждый просмотр пользователя пишется в `adminLog/{id}`: `{ at, admin, action: "user.view", target }`.
Коллекцию читает и пишет только сервер — правила её закрывают общим запретом.
Это след на случай вопроса «кто смотрел мой аккаунт».

## Данные и приватность

- Слова и наборы — личное («Your word sets and progress stay private» в Политике). Панель не
  показывает названия наборов и карточки — только сколько наборов и карточек в каждом курсе.
- Прогресс, награды и журнал тренировок видит только команда для поддержки и защиты от
  злоупотреблений — это то же основание, на котором сервер их и так считает.
- Пароли недоступны и Admin SDK.

## Клиент

- `/admin` (внутри `NavLayout`), страница грузится отдельным чанком. Без claim — «Нет доступа».
  Безопасность держит сервер; спрятанная страница — только удобство.
- Пункт «Админ-панель» в «Ещё» — только у админов.
- **Язык — русский, без i18n.** Это внутренний инструмент команды, а не интерфейс продукта:
  правило «каждая строка на 4 языках» к нему не относится.
- Поиск синхронизирован с адресом (`/admin?u=<запрос>`): ссылку на пользователя можно переслать
  коллеге, «назад» возвращает к обзору.

## Дальше

- Действия поддержки через функции `server/core` (чтобы сохранить связи прогресса), каждое —
  с обязательной причиной в журнале: восстановить орбиту после сбоя, выдать щит, вернуть капсулу.
  Правило «награды только за практику» не нарушается: это возврат потерянного, а не продажа.
- Модерация: переименовать username, отключить аккаунт.
- Обращения в поддержку в панели (сейчас только Telegram) со статусом «отвечено».
- Раздел журнала в панели.
