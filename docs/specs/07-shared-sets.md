# 07. Набор по ссылке

Человек делится своим набором ссылкой (`kolo.dakuta.dev/s/<id>`): друг, ученик или одногруппник открывает её,
видит слова и добавляет себе копию. Это не социальная функция: нет профилей, авторов, каталога и поиска —
только ссылка, которую владелец сам кому-то отдал (социальное отложено, `docs/roadmap.md`, 2026-11-08).

## Решения

- **Ссылка живая.** Сервер читает набор владельца в момент открытия: кто откроет ссылку завтра, увидит
  слова, добавленные сегодня. Отдельного снимка набора нет — нечего синхронизировать и нечему устаревать.
- **Копия — своя.** Получатель добавляет копию с чистым расписанием Perigee и дальше правит её как любой свой
  набор. Изменения оригинала в уже добавленные копии не приходят (у каждого своё расписание и свои правки).
- **Что видно по ссылке:** название, язык и слова (слово, перевод, объяснение, пример, часть речи).
  **Не видно:** прогресс и расписание, папка, имя и @имя владельца, его uid и id набора.
- **Смотреть можно без входа**, добавить — только с аккаунтом. Гость нажимает «Учить эти слова в Kolo»,
  регистрируется или входит и возвращается на ту же ссылку (`src/sharedSets/pending.ts`, сутки в localStorage).
- **Курс** — по языку набора. Нет такого курса — добавляем его вместе с набором (новичку не нужно выбирать язык
  на `/start`); курс есть, но не активный — делаем активным, ведь человек сейчас откроет этот набор.
- **Одна ссылка на набор.** «Выключить ссылку» удаляет её: старый адрес перестаёт работать у всех.
  Новая ссылка — новый адрес. Удалил набор — ссылка тоже не работает (запись реестра удаляется при первом
  открытии). Удаление аккаунта удаляет все ссылки (`/api/account-cleanup`).
- **Адрес не угадать:** 12 букв и цифр (~71 бит), выдаёт сервер. Страница — `noindex`, списка ссылок нет.

## Данные

`sharedSets/{id}` — реестр: `{ ownerUid, collectionId, createdAt }`. Пишет и читает только сервер
(Admin SDK); клиентам закрыто общим запретом в `firestore.rules`, так что правила менять не нужно.
У набора владельца новых полей нет: сервер — единственный источник правды о ссылке.
Копия получателя помечена `sharedFrom: <id>` — по ней страница ссылки показывает «Уже в твоих наборах».

## Сервер

- `server/core/shareLinks.ts` — чистые функции: id ссылки, разбор запросов, что из набора уходит наружу.
- `server/shareLinks.ts` — Firestore.
- `POST /api/share-link` (вход нужен) `{ action: "status" | "create" | "revoke", collectionId }` → `{ id | null }`.
  Ссылка уже есть — `create` возвращает её же. Чужой или несуществующий набор — 404.
- `POST /api/shared-set` (вход не обязателен, `publicHandler`) `{ id }` → `{ set, own? }`, 404 — ссылки или
  набора нет. `own` — id набора, только если открывает сам владелец.

## Клиент

- Набор: кнопка «Поделиться» рядом с «Экспортом» → `components/cards/ShareSetModal.tsx`: создать ссылку,
  скопировать, системное «Поделиться», выключить (с подтверждением в том же окне).
- `/s/:id` — `pages/shared/SharedSetPage.tsx`, своя простая шапка, работает и с входом, и без.
  Состояния: загрузка, ссылка не работает, ошибка сети, набор (гость / свой набор / уже добавлен / добавить).
- Сборка копии — `src/sharedSets/build.ts` (с тестами): новые id, чистое расписание, `createdAt` по порядку
  слов — Perigee вводит новые слова в порядке набора.

## Не делаем сейчас

- Превью ссылки в мессенджерах с названием набора (нужна серверная отрисовка `<meta>` для `/s/*`).
- «Пожаловаться на набор»: ссылки не публичны, найти их можно только от владельца. Если понадобится —
  команда удаляет запись `sharedSets/{id}` вручную.
- Обновление уже добавленных копий из оригинала.
